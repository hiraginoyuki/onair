Adds native Anthropic Messages API proxy on `POST /v1/messages` alongside the OpenAI Chat Completions and Responses surfaces.
Public model names map to backend models on the request and rewrite back on the response, including streaming SSE frames.

## What's new

- `POST /v1/messages` accepted (sync and streaming) alongside the OpenAI
  surfaces. Toggled by `expose = ["messages"]` on the route and
  `supports = ["messages"]` on the backend.
- New inbound auth: `x-api-key`. `Authorization: Bearer` still works and
  wins on conflict.
- Default `anthropic-version: 2023-06-01` is injected when the client
  omits it. Pin a different version per route under
  `[route.request_headers] anthropic-version = "..."`; the route value
  overrides both the client value and the default.
- `max_tokens` fallback: when the client omits it, the route's
  `anthropic_max_tokens` value is used. Missing both returns
  `400 invalid_request_error` in the Anthropic envelope.
- `/v1/messages` paths emit errors in the Anthropic envelope
  (`{"type":"error","error":{...}}`); other paths keep the OpenAI shape.
- Opt-in `stream_capture = true` per route or per backend records
  upstream and client SSE events to disk for debug. Default off;
  async best-effort writer with a bounded channel.

## Compatibility

OpenAI-only operators see no change. The new surface is additive and
toggles entirely on the `messages` marker.

## Reserved / forthcoming

The Anthropic → OpenAI Chat compat layer
(`messages_via_chat_completions`) is forthcoming.

## Migration

No config migration required.
