# Release notes - v0.2.1

> Long-form release notes kept in the source tree. The public release
> body mirrored to the GitHub release page is the short form at
> [v0.2.1-short.md](v0.2.1-short.md).

**Release date:** 2026-07-09 JST
**Diff from `v0.2.0`:** OpenAI Chat Completions to Anthropic Messages
compatibility, version bump, and release-candidate fixes.

## Highlights

- **OpenAI Chat -> Anthropic Messages compatibility.** OpenAI Chat
  Completions clients can now route to upstream `/v1/messages`
  backends through the explicit `chat_completions_via_messages`
  marker.
- **Config alias for shorter local config.** `chat_via_messages` is
  accepted at config load and immediately canonicalized to
  `chat_completions_via_messages`. Resolved config, operator
  snapshots, and logs use the canonical marker.
- **Streaming Chat shape from Anthropic SSE.** Anthropic Messages
  streaming events are translated to Chat Completions streaming chunks,
  including assistant text deltas, tool-call deltas, finish reasons,
  and `[DONE]`.
- **Chat usage opt-in is accepted.** `stream_options.include_usage`
  is accepted on `chat_completions_via_messages` requests. The
  compatibility layer does not forward `stream_options` upstream
  because Anthropic Messages does not use that field.
- **No synthetic zero-usage stream chunk.** If an Anthropic streaming
  backend omits usage, onair no longer fabricates a final Chat usage
  chunk containing zero token counts. A final usage chunk is emitted
  only when upstream usage was actually observed.

## New route shape

```toml
[[backend]]
id = "anthropic-wrapper"
base_url = "http://127.0.0.1:8002"
supports = ["messages", "streaming", "tools"]

[[route]]
public = "gpt-4o-anthropic"
expose = ["chat_completions_via_messages", "tools"]
backends = ["claude-sonnet-4@anthropic-wrapper"]
anthropic_max_tokens = 4096
```

The selected backend must still be Anthropic Messages-capable via
`supports = ["messages"]`. `messages` alone does not imply the
compatibility path; the route must explicitly expose
`chat_completions_via_messages` or the config-load alias
`chat_via_messages`.

## Compatibility

- **Config:** backward-compatible. The new marker only affects routes
  that opt in explicitly. Existing OpenAI-only and native Anthropic
  routes continue to resolve as before.
- **Wire protocol:** additive. OpenAI Chat Completions clients keep the
  Chat response shape while onair talks to an upstream Anthropic
  Messages backend.
- **Routing:** direct OpenAI Chat and the existing
  `chat_completions_via_responses` path are preferred before
  `chat_completions_via_messages` when multiple explicit options are
  available for a route.
- **Usage:** streaming usage is forwarded to Chat clients only when an
  upstream Anthropic Messages SSE event includes usage.

## Internals touched (representative)

- `crates/onair-core/src/openai/anthropic_compat.rs` - Chat
  Completions request/response translation for Anthropic Messages.
- `crates/onair-core/src/openai/request.rs` - dispatch to
  `RequestMode::ChatCompletionsViaMessages` and upstream path rewrite
  to `/v1/messages`.
- `crates/onair-core/src/openai/response.rs` -
  `AnthropicMessagesToChatSseNormalizer` and buffered response
  translation back to Chat Completions.
- `crates/onair-core/src/config.rs` - marker canonicalization and
  `chat_via_messages` alias handling.
- `crates/onair-proxy/src/routing.rs` - explicit Messages-backed Chat
  route selection.
- `crates/onair-proxy/src/proxy.rs` - Anthropic version header handling
  for the compatibility path.
