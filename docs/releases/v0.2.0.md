# Release notes — v0.2.0

> Long-form release notes kept in the source tree. The public release
> body mirrored to the GitHub release page is the short form at
> [v0.2.0-short.md](v0.2.0-short.md).

**Release date:** 2026-06-30 JST
**Diff from `v0.1.0`:** 27 commits (Phase 0 groundwork + Phase 1 native
Anthropic Messages API proxy + 1 local main fixup + Phase 1 docs).

## Highlights

- **Native Anthropic Messages API proxy.** `POST /v1/messages` sync and
  streaming are accepted alongside the existing OpenAI Chat Completions
  and Responses surfaces. Public model names are mapped to backend
  models on the request side and rewritten back on the response side,
  including in streaming SSE frames.
- **New inbound auth: `x-api-key`.** Anthropic-style auth is now
  accepted in addition to `Authorization: Bearer`. Bearer wins on
  conflict (matches Anthropic's own precedence).
- **Default `anthropic-version` injection.** Requests without the
  header receive `anthropic-version: 2023-06-01`. Operators who want
  a different upstream version pin it under
  `[route.request_headers] anthropic-version = "..."`; the route
  value overrides both the client value and the default.
- **`max_tokens` fallback.** Anthropic requires `max_tokens`. When the
  client omits it, the route's `anthropic_max_tokens` value is used.
  If both are missing, the request returns
  `400 invalid_request_error` in Anthropic error format.
- **Anthropic-format error envelope on `/v1/messages` paths.**
  OpenAI-format errors elsewhere.
- **Streaming debug capture.** New opt-in `stream_capture = true` per
  route or per backend records upstream and client SSE events to disk
  with monotonic `ts_us` per event. Default off. Async best-effort
  writer with a bounded channel so it never blocks the stream.

## New per-route config

```toml
[[backend]]
id = "local-llama"
base_url = "http://127.0.0.1:8080"
supports = ["messages", "streaming", "tools"]

[[route]]
public = "claude-local"
expose = ["messages"]
backends = ["llama-3.1-8b-instruct@local-llama"]
anthropic_max_tokens = 4096

[route.request_headers]
# anthropic-version = "2023-06-01"
# x-api-key = "backend-specific-key"
```

This block is fully commented out at the end of `onair.example.toml`
with a working `# Example Anthropic Messages API route` template.

`request_headers` is general-purpose and the second Phase 0 feature; it
allows arbitrary upstream header injection on any route, not only
Anthropic routes. See
[`docs/configuration.md` §"Anthropic Messages API"](docs/configuration.md#anthropic-messages-api).

## Breaking Changes

**None for OpenAI-only operators.** The new surface is additive and
toggles entirely on `expose = ["messages"]` and
`supports = ["messages"]`. Operators not using these markers see no
change.

For Anthropic operators, the error shape on `/v1/messages` paths is
deliberately the Anthropic shape (`{"type":"error",
"error":{...}}`) instead of the OpenAI shape. This is a deliberate
choice to keep Anthropic clients working without client-side envelope
parsing changes.

## Compatibility

- **Config:** backward-compatible. All new fields are optional with
  defaults that preserve prior behavior.
- **Wire protocol:** a *new* protocol is added (`/v1/messages`). The
  OpenAI Chat Completions, OpenAI Responses, and embedding surfaces
  are unchanged.
- **Markers:** the new `messages` marker is added to the allowlist in
  `KNOWN_MARKERS`. Routes or backends carrying it must additionally
  carry `messages` for `request_mode_for_messages()` to select them;
  routes carrying only `messages_via_chat_completions` continue to
  trigger the unknown-marker warning and remain unimplemented
  pending Phase 2.
- **Auth:** `x-api-key` is *additive*. Existing `Authorization: Bearer`
  callers see no change.

## Migration

1. Existing configs continue to parse and run unchanged.
2. To enable the Anthropic surface: add `supports = ["messages"]`
   to a `[[backend]]` and `expose = ["messages"]` to a
   corresponding `[[route]]`. Set `anthropic_max_tokens` per route.
3. To pin an upstream `anthropic-version`, add
   `[route.request_headers] anthropic-version = "..."` to the
   route. To override `anthropic-version` for the upstream backend
   while still injecting the route-preferred value into headers,
   see `docs/configuration.md#anthropic-version-resolution-order`.
4. To forward a backend-specific API key, prefer
   `[route.request_headers] x-api-key = "..."` over the global
   `[[backend]].api_key` (which the proxy currently sends as
   `Authorization: Bearer`). Configuring both is discouraged
   because Anthropic accepts both headers and the duplicate
   auth is fragile.
